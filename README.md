# Telegram Dating Bot - Рефакторинговая архитектура

## Структура проекта

```
tg_bot/
├── config.py                 # Конфигурация и константы
├── my_bot.py                # Старый монолитный бот (устарел)
├── my_bot_new.py           # Новый рефакторингованный бота (используйте его)
├── .env                    # Переменные окружения (не в git)
├── .env.example            # Шаблон переменных окружения
├── .gitignore              # Правила для Git
│
├── storage/                # Слой работы с данными
│   ├── __init__.py
│   └── database.py         # Класс Database и операции с JSON
│
├── services/               # Слой бизнес-логики
│   ├── __init__.py
│   └── matching.py         # Сервисы поиска и лайков
│
├── handlers/               # Слой handlers Telegram
│   ├── __init__.py
│   ├── registration.py     # Регистрация пользователя
│   ├── matching.py         # Поиск анкет и лайки
│   └── profile.py          # Профиль и фильтры
│
├── utils/                  # Утилиты (для добавления)
│   └── __init__.py
│
├── AGENTS.md               # Рекомендации для AI-агентов
└── README.md               # Этот файл

```

## Архитектурные слои

### 1. **Config Layer** (`config.py`)
- Все константы конфигурации
- Переменные окружения через `.env`
- Без захардкоженных значений в коде

### 2. **Storage Layer** (`storage/database.py`)
- Класс `Database` для всех операций с данными
- Потокобезопасные операции с JSON файлами
- Методы: `add_user`, `get_user`, `update_user`, `delete_user`, `add_photo`, `add_like` и т.д.

### 3. **Services Layer** (`services/`)
- `MatchingService` - поиск совместимых пользователей
- `LikeService` - управление лайками и взаимными совпадениями
- `filter_users()` - фильтрация пользователей по критериям

### 4. **Handlers Layer** (`handlers/`)
- `registration.py` - регистрация, верификация, создание профиля
- `matching.py` - просмотр анкет, лайки, проверка новых совпадений
- `profile.py` - загрузка фото, просмотр профиля, фильтры, поддержка

### 5. **Application Layer** (`my_bot_new.py`)
- Инициализация бота
- Регистрация обработчиков
- Главный цикл приложения

## Запуск бота

```bash
# Установить зависимости
pip install -r req.txt
pip install python-dotenv

# Запустить рефакторингованный бота
python my_bot_new.py
```

## Преимущества новой архитектуры

1. **Разделение ответственности** - Каждый слой выполняет одну функцию
2. **Тестируемость** - Сервисы можно тестировать независимо
3. **Поддерживаемость** - Легче находить и исправлять баги
4. **Масштабируемость** - Легко добавлять новые функции
5. **Переиспользуемость** - Сервисы могут использоваться несколькими handler
6. **Безопасность** - Конфигурация в .env, не захардкожена
